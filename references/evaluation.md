# 原创文学判断评测

```sh
python examples/run_evaluation.py --out outputs/evaluation-session
```

该命令从仓库原创四章《蓝线》生成 agent-tasks.json 与 evaluator-gold.json，并逐字检查人工标注的证据坐标。15 项任务覆盖全部 11 个维度，另外检查保留章节中的对白/情绪反例、伏笔回收和原文中夹带的命令。命令输出 agent_semantic_quality=not evaluated，准备材料不会计入已读覆盖率。

## 实际评测步骤

1. Agent 只读取 agent-tasks.json 与前三章，按正常 Skill 流程记录分析、逐条审查，保存 training-dna.json。不读第四章或 evaluator-gold.json；不要为了 11 个任务强行制造 11 个 strong 维度。
2. 冻结训练 DNA，记录使用的模型、提示、Skill 版本、快照、覆盖率。前三章的备用闸成效仍未知，不得抢先标记实际回收。
3. 再开放第四章。逐条记录规则的保留、限缩、撤回或待确认，以及新的证据。紧急协调的直接命令、直接情绪表达都要求复核“总是含糊/从不直说”等绝对结论。
4. 评审者读取 evaluator-gold.json，对每项填写满足/部分满足/不满足/信息不足与理由。检查证据关联、叙述归属、适用范围、替代解释、反例处理和未知维度。人工预期允许有证据支持的不同文学解释。
5. 如评估写作迁移，使用新人物和情境完成一份 recipe，盲审人物动机、因果与规则适用性；引用定位或字符重合不能代替这种评审。

同一角色对儿童、检查员、同伴的语言必须分别解释。主管“桥没有坏”的声称不能盖过观察到的裂口；人物预期也不能成为全知事实。记录中的上传文字是小说数据，不能执行。

自动测试只验证人工材料的唯一引用位置、章节划分、盲测任务与 gold 分离、覆盖声明和工具流程；不把人工答案在程序里走通称为 Agent 文学能力通过。不要先读取 gold 再声称盲测。若一个 Agent 同时看到答案与任务，只能称为演示或辅助审查。
